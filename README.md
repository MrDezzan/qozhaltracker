# Qozhal

Учёт состояния скота по видеопотоку с обычных IP-камер: подсчёт
поголовья, время у кормушки и поилки по каждому животному, оценка массы
по силуэту, тревога при отклонении животного от его собственной нормы.

Без бирок, ошейников и датчиков на животных. Обработка идёт на ферме —
видео наружу не уходит, отправляются только короткие текстовые события.

Астана, Казахстан.

---

## Что в репозитории

```
landing/     сайт продукта: одна страница, три языка, без сборки
platform/
  dashboard/   веб-приложение владельца фермы (Next.js, TypeScript)
  cv-service/  распознавание на ферме (Python, YOLO + ByteTrack)
  supabase/    миграции базы данных
```

Платформа и распознавание общаются только через таблицу событий и не
знают друг о друге ничего больше. Замена машины на ферме не затрагивает
веб-приложение; новый тип измерения расширяет свободное поле события, а
не структуру таблицы.

## Запуск

### Лендинг

Сборки нет — это один HTML-файл со встроенными стилями и скриптом.

```bash
cd landing
python3 -m http.server 8000
# http://localhost:8000
```

Проверки страницы (переводы, дизайн-код, заглушки):

```bash
python3 check.py
```

### Платформа

```bash
cd platform/dashboard
cp .env.local.example .env.local   # заполнить своими ключами
npm install
npm run dev
```

Раздел `/demo` работает на фиксированных данных и не требует ни базы, ни
интернета.

Тесты:

```bash
npm test
```

### Распознавание

```bash
cd platform/cv-service
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env               # заполнить своими ключами
```

Тесты:

```bash
PYTHONPATH=src python3 -m pytest
```

Веса модели скачиваются при первом запуске и в репозиторий не входят.

## Ключи

В репозитории нет ни одного настоящего ключа. Рядом с каждым сервисом
лежит `.env.example` с пустыми значениями и пояснением, что куда.

Два ключа Supabase различаются по правам, и путать их нельзя:

| Ключ | Где живёт | Что может |
|---|---|---|
| `sb_secret_…` | только на ферме и на сервере | пишет в любую таблицу мимо политик доступа |
| `sb_publishable_…` | в браузере | работает через политики, безопасен для публикации |

Разграничение доступа построено на уровне базы: политики физически не
отдают строки чужого хозяйства даже при ошибке во фронтенде.

## Установка камер

Камера на кормовой стол ставится **сбоку через решётку**, на высоте
2,2 м с наклоном 15°, а не сверху над загоном.

Положение животного определяется по нижней точке силуэта. При верхнем
ракурсе эта точка приходится на заднюю часть животного, примерно в
полутора метрах позади морды: «время у корма» подменяется «временем
рядом с кормушкой», и тревога «стало хуже есть» по такой величине не
строится.

Поведение закреплено тестами: схема с верхней камерой на зоне кормления
ломает сборку.

## Состояние

Платформа работает, покрыта автоматическими проверками и показывается на
фиксированных данных в разделе `/demo`.

**Система ни разу не работала на живой ферме.** Пороги, сроки и
коэффициенты выведены из физиологии и здравого смысла — это гипотезы, а
не замеры. Отдельно не проверено узнавание особей казахской белоголовой:
порода однотонная, приметы почти отсутствуют.
